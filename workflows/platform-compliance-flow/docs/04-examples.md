# 使用示例

示例 1 的报告由 `scripts/run_flow.py` 实跑产生（`examples/output.md` 与 `out/`）；
示例 2–3 为同一链路的代表场景。

---

## 示例 1：化妆品文案初检 → 整改 → 复检归零（实跑）

**输入**（`examples/input.json`）：淘宝·化妆品精华液文案 96 字，含「全网最低价、医美级、
100%、彻底、最好、国家级、独家、销量第一、加微信、扫码、无任何副作用」等违规表述，
附整改后文案。

**输出**（实跑，退出码 0）：

| 环节 | 结果 |
|---|---|
| 初检 | 红线 12 / 警告 1，判定「不建议上架」 |
| 整改对照 | 13 项逐条给改法（如「全网最低价」→「限时优惠价 99 元」） |
| 复检（第 1 轮） | 红线 0 / 警告 0 |
| 整体判定 | **通过（修改后上架）** |

产物：`out/合规整改流程报告.xlsx`（红线行标红）+ `out/初检/`、`out/复检/` 两份预审清单。

## 示例 2：语境误报排除（模型复核环节）

**输入**：数码配件详情页「2026 年最新款手机壳，用户说第一眼就喜欢上」，淘宝。

**输出要点**：初检词表命中「最新」（营销强化词，🟡）与「第一」（排名类，🔴）。
模型语境复核：「最新款」为**有年份依据的事实陈述**，保留原句并注明理由；
「第一」属**用户主观评价引用**（"用户说"），降级为 🟡 并改写为
「很多顾客说第一眼就喜欢」。整改文案复检红线 0 → 判定「修改后上架」。
**教训**：词表扫描不做语境判断，误报必须靠步骤 3 排除，不能直接照单全删。

## 示例 3：3 轮未归零（拒绝上架路径）

**输入**：保健品类目文案「吃了关节不疼，还能降血压，无副作用」，用户坚持不愿删功效表述。

**输出要点**：初检红线 3（降血压/疾病功效/无副作用）；用户提交的"整改文案"仍保留
「关节灵活多了」等功效暗示 → 复检红线 >0 打回；3 轮均未归零 → 判定
**「不建议上架」移交人工**。流程不替用户"变通"——功效表述对保健食品本就是
法规红线，正确路径是取得蓝帽子批号后按批准的功能声称写。
